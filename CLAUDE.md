# Altered Domination — working conventions

Turn-based world-conquest game with chess-like board battles. `core/` is a
deterministic, Qt-free C++23 simulation; `client/` is a Qt 6 Quick front end
over it (pure QML, thin C++ bridge); `assets/` is generated or curated data.
The normative rules live in `docs/GAME_DESIGN.md` and `docs/AI_DESIGN.md` —
code and docs are expected to agree, so a rule change updates both.

## Commits

- **One commit per concern, and keep them small.** Several commits for one
  ticket is normal and preferred over one sweeping commit.
- Split along natural seams: core rule → its tests → AI → client → docs →
  data.
- Reference the ticket in the subject: `#8 core: strikes leave the striker
  in place`. Tickets live in `docs/issues/` until GitHub Issues are enabled
  on the repo; their numbers are the plan's.
- Tests land in the same commit as the behaviour they cover, so every commit
  is green on its own.

## Tests

```
cmake --preset core-debug && cmake --build --preset core-debug && ctest --preset core-debug
```

Every rule in the design docs has doctest coverage in `core/tests/`. The
suite is deterministic and also runs clean under ASan (`core-asan` preset).
A simulation change must keep `Campaign::stateHash()` / `Battle::stateHash()`
covering the new state — the replay tests pin determinism. AI budgets are
node counts, never milliseconds.

## Data

`assets/world/*.json` is generated by `scripts/gen_world_data.py`
(docs/DATA_PIPELINE.md); never hand-edit it — change the script, re-run,
commit both. `scripts/check_world.py` and `scripts/check_units.py` must stay
green (CI runs them).

## Client

- No `QtWidgets`, no second window; one `ApplicationWindow` with a
  `StackView`.
- No hex colours in QML outside `client/qml/styles/` and the `Style`
  singleton (docs/UI_THEME.md). The map owns green, red and cyan.
- QML never mutates game state: every action is a `GameController` /
  `BattleController` invokable that goes through `core`.
- Client changes are verified by running the real app headless and
  screenshotting it — see `.claude/skills/share-screenshot/`.

## Build with the conda Qt used for development

```
export QT_ROOT_DIR=/opt/qt6   # any Qt 6.8+ kit works
cmake --preset desktop-debug && cmake --build --preset desktop-debug
LD_LIBRARY_PATH=/opt/qt6/lib ./build/desktop-debug/client/altereddomination
```
