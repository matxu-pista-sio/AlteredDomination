# Data pipeline — the world, the units, the flags

Everything the game knows about the Earth is generated by
`scripts/gen_world_data.py` from public sources, committed as JSON under
`assets/world/`, and never edited by hand. Re-running the script with the
same inputs and the same `--seed` produces byte-identical output.

## 1. Sources

| Data | Source | File | License |
|---|---|---|---|
| Country polygons, ISO codes, population, GDP fallback | Natural Earth 1:50m `admin_0_countries` (v5.1.x) | `ne_50m_admin_0_countries.geojson` | public domain |
| Cities (name, lon/lat, population, capital flag) | Natural Earth 1:10m `populated_places_simple` | `ne_10m_populated_places_simple.geojson` | public domain |
| GDP (current USD, latest year per country) | World Bank NY.GDP.MKTP.CD via [datasets/gdp](https://github.com/datasets/gdp) | `gdp.csv` | PDDL / World Bank CC-BY 4.0 |
| Flags | [lipis/flag-icons](https://github.com/lipis/flag-icons) 4×3 SVGs | `assets/flags/<iso2>.svg` | MIT |

The raw files are cached in `.cache/raw/` (gitignored); `--fetch` downloads
them from the pinned raw.githubusercontent.com URLs in the script header.

## 2. Countries — which ones play

A Natural Earth feature becomes a playable country when **all** hold:

1. it has an ISO alpha-2 code (`ISO_A2_EH`, which fixes France, Norway,
   Kosovo `XK`, Taiwan `TW`), and is not Antarctica;
2. `POP_EST ≥ 50 000` — a country needs people to have a city;
3. at least one populated place of Natural Earth's 1:10m set lies in it
   (matched by `iso_a2`, falling back to a point-in-polygon test for the
   few places whose code is `-99`).

Dependencies and disputed territories that pass (Puerto Rico, Hong Kong,
Western Sahara, Palestine, Greenland, New Caledonia, …) are countries in
the game exactly like the legacy map treated them; the generator writes
`"sovereign": "<iso2>"` for information only. Somaliland and Northern
Cyprus have no ISO code and are folded into Somalia and Cyprus.

The result is ≈ 190 countries. `name` is Natural Earth's `NAME_LONG`
where `NAME` is an abbreviation ("Dem. Rep. Congo" → "Democratic Republic
of the Congo"), `key` is the lower-case ISO code.

## 3. Projection

**Miller cylindrical**, longitude −180…180 → `x ∈ [0, 4096]`, latitude
clipped to `[-56°, 84°]` (nothing playable lies outside) →
`y ∈ [0, ≈1963]`, `y` growing southward:

```
x = (lon + 180) / 360 · 4096
y = (yMiller(84°) − yMiller(lat)) · 4096 / 2π
yMiller(φ) = 1.25 · ln(tan(π/4 + 0.4 · φ))
```

The map is therefore one rectangle, seams at the antimeridian; the client
may draw a second copy for wrap-around panning. All coordinates in the
JSON are in these map units, rounded to 0.1.

## 4. Cities — cropping to ~1000

The legacy map had 972 hand-picked cities; the generator keeps the same
shape of the world (every country present, big countries dense) from real
data:

1. **Quota** per country: `q = clamp(1, 60, round(kCityBudget · (0.55 ·
   popShare + 0.45 · areaShare)))` with `kCityBudget` chosen so that the
   quotas sum to ≈ 1 000; `popShare`/`areaShare` are the country's share of
   world population / land area. (Population alone starves Canada and
   Australia; area alone floods them.)
2. **Candidates**: the country's populated places sorted by priority —
   the capital first (`adm0cap == 1`), then `pop_max` descending; places
   without a population count last.
3. **Spacing**: a candidate is skipped when an already-accepted city of the
   same country lies within `kMinCitySpacing = 14` map units (≈ 0.34 % of
   the map width; roughly 120 km at the equator), so markers never
   overlap at the default zoom. The capital is always accepted.
4. Take candidates until the quota is met. A country whose places are all
   too close ends with fewer cities, never zero.

Each city gets `key = "<iso2>-<slug(name)>"` (unique; a numeric suffix on
collisions), `tier` (GAME_DESIGN.md §1) and `isCapital`.

## 5. Links

The link graph is built on the projected points:

1. Delaunay triangulation of all cities (`scipy` is not a dependency: the
   script carries a small Bowyer–Watson).
2. Keep every edge with length ≤ `kLandLink = 140` map units (≈ 1 200 km).
3. Compute the minimum spanning tree of the *full* Delaunay graph and add
   every MST edge that is missing — this is what connects islands and
   continents through their shortest crossings (Bering Strait, Gibraltar,
   Sicily–Tunisia, Indonesia–Australia, Iceland …) and guarantees the
   graph is connected.
4. Any edge longer than `kLandLink` is flagged `"sea": true` and drawn
   dashed.

Every link is stored once (`a < b`) and both cities list it; the tests
assert symmetry, connectivity and that no city is isolated.

## 6. Territories and colours

- **Territory**: the Voronoi cell of the city (all cities of all countries
  together, so borders between countries stay where Natural Earth draws
  them) **intersected with its own country's polygon**. Cells are simplified
  with a 0.8-map-unit tolerance and written as SVG path strings
  (`M x y L x y … Z`, multiple subpaths for multipolygons). Islands of a
  country that contain no city fall to the nearest city of that country.
- **Country outline**: the Natural Earth polygon, simplified with the same
  tolerance, as one path string per country (for the border layer).
- **Banner colour**: assigned by the generator from a 48-hue table so that
  no two countries that touch on the map share a hue (greedy colouring in
  descending population order); saved per country, part of the data so
  the legend is stable across runs.

## 7. Units

`assets/units/units.json` is curated (not generated) but validated by
`scripts/check_units.py`: every type has `key`, `name`, `cost`,
`classes ⊆ {human, machine, land, air}` (exactly one of human/machine, one
of land/air), `moves[]` and `strikes[]` with integer offsets, `path[]`
offsets and `affects ⊆ classes`. The icons in `assets/units/icons/<key>.svg`
are generated by `scripts/gen_unit_svgs.py` (64×64 viewBox, pure white
strokes on transparency, gradients and filters allowed — the client draws
the banner-coloured disc beneath). The pattern diagrams shown in the codex
are drawn by QML from the same JSON.

## 8. Output files

| File | Contents |
|---|---|
| `assets/world/world.json` | `{"version", "projection", "generated", "sources", "countries": [...], "cities": [...], "links": [...]}` |
| `assets/world/territories.json` | `{"<cityKey>": "<svg path>"}` |
| `assets/world/outlines.json` | `{"<iso2>": "<svg path>"}` |
| `assets/flags/<iso2>.svg` | one flag per country |
| `assets/units/icons/<key>.svg` | one icon per unit type |

`world.json` also carries `"hash"` — the SHA-256 of its own canonical
content — which saves record (GAME_DESIGN.md §10).
