# [Core] Save/load: versioned JSON schema with world hash and RNG state; fixes the gamesaves.json/gameSaves.json split

Labels: enhancement, bug · Type: Feature

## Reported
> overall better project design

## What happens today
- `MapView::saveGame` writes `QDir::currentPath()/gamesaves.json`; `HomeMenu` reads `QDir::currentPath()/gameSaves.json` (`mapview.cpp:334`, `homemenu.cpp:24`) — different file on case-sensitive systems, and the working directory is wherever the game was launched from.
- `autoSave` removes element 0 of the array and inserts itself (`mapview.cpp:377`), clobbering whichever save happened to be first.
- The save stores zoomed pixel coordinates (see #5) and no schema version; unit ids restart at 0 on load.

## Change
`core/include/ad/core/save.hpp` per [docs/GAME_DESIGN.md](https://github.com/matxu-pista-sio/AlteredDomination/blob/claude/dreamy-volta-pvb4kh/docs/GAME_DESIGN.md) §10:
- `toJson(const Campaign&) → std::string` and `fromJson(std::string_view, const World&, const Catalog&) → expected<Campaign, Error>`; schema `"version": 1`, `"world_hash"` checked against the loaded world, settings, round, current turn, countries (funds, eliminated, isHuman, personality), cities (owner, units with ids/types/acted), RNG state, next unit id.
- Client-side (`SaveStore`, in #18): slots under `QStandardPaths::AppDataLocation/saves/`, sidecar metadata, `autosave` slot written at the end of every round.
