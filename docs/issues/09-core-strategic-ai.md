# [Core] Strategic AI: threat analysis, counter-based recruitment, scored attacks, reinforcement flow, four personalities, resumable AiRound

Labels: enhancement · Type: Feature

> improve the Ai layout and logic

## What happens today
- `MapAI::distributeFunds` (`AI/mapai.cpp:257-330`) buys from three hard-coded "widraw" lists picked by fund bracket (≤100 / <500 / ≥500), never looking at what the enemy fields; the `choosingMatrix` built in the constructor is never read.
- `moveUnitsToFrontLine` (`mapai.cpp:352-385`) only moves units one hop when a neighbour's neighbour is foreign; the `/// layer 2` branch is an empty comment, so interior armies never reach a front.
- `StudyAttackPossibilities` (`mapai.cpp:387-420`) attacks any neighbour with less than half its power, picked with `qrand()`; no value, no garrison.
- The AI runs on the UI thread and, for human battles, calls `mapView()->citiesGraphics().value(...)->startBattle()` (`mapai.cpp:launchBattleAI_Player`), i.e. drives the widgets.

## Change
`core/include/ad/core/ai/strategic.hpp` per [docs/AI_DESIGN.md](https://github.com/matxu-pista-sio/AlteredDomination/blob/claude/dreamy-volta-pvb4kh/docs/AI_DESIGN.md) §1–§2:
- Per-turn analysis (power, enemy pressure, frontier flag, BFS distance to the front, targets).
- Recruitment: defence first, then expansion; composition from the counter table (AA vs air, rocket/tank/MLRS vs machines, AFV/sniper/helicopter vs humans); every purchase validated as `Campaign::apply` would.
- Attacks scored by `winEstimate · value`, thresholds and garrison rules per personality; undefended targets always taken.
- Reinforcement one hop along shortest paths toward the front, garrison kept.
- Personalities Expansionist / Balanced / Defensive / Opportunist drawn from `hash(seed, key)`.
- `AiRound`: resumable stepper emitting `Progress` events and stopping on `BattleNeedsHuman` until `resumeWithBattleResult` (ARCHITECTURE.md), so the client runs it on a worker thread.
