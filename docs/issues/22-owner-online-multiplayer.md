## What happens today
`multiplayer/multiplayergame.cpp` and `homemenu.cpp:entermatchmaking` connect to a matchmaking server at a user-typed address on port 17777 and exchange length-prefixed JSON; the server is not in the repository, the protocol has no version, and the battle is driven by replaying mouse events (`MultiplayerGame::messageReceived` calls `mousePressEventAI()`). The modernization removes this code (#1) and adds **hotseat** (two humans on one machine, GAME_DESIGN.md §7).

## Decision needed (owner only)
Online play needs a server somebody hosts (TopGen's `topgen-server` — WebSockets + SQLite, accounts, ELO, hosted simulation — is the obvious template). Decide:
1. Whether online multiplayer is wanted for this game at all, and in what form: duel battles only (the legacy idea) or full shared campaigns (turn-based lockstep, much simpler than TopGen's real-time hosting).
2. Who hosts it (a VPS you own, the same box as TopGen's server, or nothing yet).

## Proposed shape (for when the decision is yes)
- Reuse TopGen's server skeleton and protocol conventions (PROTOCOL.md there); a `Campaign` is deterministic and command-driven, so a shared campaign is "one host applies commands and broadcasts the command log"; board battles between two humans are two command streams to one `Battle`.
- Ticketed as its own milestone after the desktop game ships.

## Acceptance criteria
- A decision recorded in this issue; follow-up tickets filed from it.
