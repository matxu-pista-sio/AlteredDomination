# [Core] World and unit catalog: immutable data model loaded from the generated JSON, validated, indexed

Labels: enhancement · Type: Feature

## Reported
> overall better project design [...] improve the Ai layout and logic

## What happens today
- Every domain object is a `QObject` with `Q_PROPERTY` boilerplate (`domain/city.h` alone declares 13 properties with signals); containers are returned by value and copied on each access (`city->units().values().at(i)` in `AI/mapai.cpp:343`), so loops are quadratic and iteration order undefined.
- Raw `new` without parents everywhere, `deleteLater` on units still referenced from lists (`AI/mapai.cpp:310-370`).
- `Unit::idCount` is a process-wide static (`domain/unit.cpp:4`): ids restart at 0 per game and collide after a load.
- City coordinates are mutated on every zoom (`graphics/citygraphics.cpp:zoomChanged` multiplies `x/y` by the zoom ratio), so positions drift and saves store zoomed pixels.

## Change
`core/include/ad/core/{world,catalog,constants,rng}.hpp` ([docs/ARCHITECTURE.md](https://github.com/matxu-pista-sio/AlteredDomination/blob/claude/dreamy-volta-pvb4kh/docs/ARCHITECTURE.md)):
- `World` — plain value types: `Country{key, name, color, capitalCity, gdp, population, continent}`, `City{id, key, name, country, x, y, lon, lat, population, tier, isCapital, links[]}`, `Link{a, b, sea}`; loaded by `World::fromJson(std::string_view)` with full validation (unique keys, dense ids, symmetric links, capital exists) that reports errors instead of asserting.
- `Catalog` — `UnitType{id, key, name, cost, classes, moves[], strikes[]}` from `units.json`; `unitTypeByKey`, class predicates (`affects(type, target)`).
- `constants.hpp` with every number of GAME_DESIGN.md §11; `Rng` (SplitMix64) with `state()`/`seed()` for the save.
- Data files reach the core as byte strings — the client owns paths; tests load the committed assets through a `AD_ASSETS_DIR` compile definition.
