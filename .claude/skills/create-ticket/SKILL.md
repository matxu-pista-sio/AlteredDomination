# Create a ticket

Tickets follow one format so a reader can act on them without the
conversation that produced them. GitHub Issues are disabled on the
repository at the time of writing, so tickets live in `docs/issues/NN-slug.md`
and `docs/issues/README.md` indexes them; when Issues are enabled, file the
same text as an issue and keep the number.

## Format

```
# [Area] One-line title in the imperative

Labels: bug | enhancement · Type: Bug | Feature | Task

## Reported
> the user's words, or the observation, verbatim

## What happens today
- the current behaviour, with file:line references

## Change
- what to build, per the design docs (link them)

## Acceptance criteria
- observable checks, screenshots to attach, commands to run
- Suggested commits: `#NN area: one concern`, ...

Related: #NN, #NN.

---
_Generated by [Claude Code](https://claude.ai/code)_
```

## Rules

- One concern per ticket; a ticket that needs the owner (a licence, a
  credential, a product decision) says so in its title: `[Owner action]`.
- Reference the design doc a change follows; never restate a rule that a
  doc owns.
- Commits reference the ticket number in the subject (`#12 client: ...`).
- When the work is done, append a `## Done` section with the commits and
  the screenshots, and tick it in `docs/issues/README.md`.
